# 术语统一规范（项目强制）

> 本文件是**术语的唯一权威定义**。改任何文案前先查此表，避免再次混用。
> 2026-10-04 建立。此前仓库同时存在「宿主」「软件主体」「Native Host」三种叫法共 84 处。

## 一、本项目的两个程序

本项目只有**两个**可执行程序 + 一个前端资源目录：

| 称呼（唯一标准） | 技术标识符（**不要改**） | 是什么 | 用户怎么启动 |
|---|---|---|---|
| **主程序** | `fs-gui` / `crates/gui` | 桌面主程序（Tauri 2 + WebView2），带主窗体、全局热键、截图 OCR 翻译、设置抽屉 | 双击 `fs-gui.exe` |
| **浏览器扩展** | `extension/` | Chromium MV3 扩展，划词 / 全文 / 侧栏 / 截图翻译 | 浏览器加载已解压的扩展 |
| **NM 桥**（仅指机制） | `fs-host` / `crates/host`、`com.fullscene.ocr_translator` | 扩展与主程序之间的 Native Messaging 管道。**它是通道，不是"程序"** | 不用手动启动 |

## 二、强制用语

### ✅ 统一用「主程序」

指 `fs-gui` 这个桌面程序。所有**用户可见文案**与**代码注释**一律用它：

- ✅ `未检测到主程序，请先安装并启动`
- ✅ `SelectCapture 需主程序主窗体运行`
- ✅ 注释：`/** 强调色变更（即时生效，主程序同步写回 Rust 配置） */`
- ✅ 注释：`crates/gui`（主程序）与 `crates/host`（NM 桥）共同依赖 fs-core

### ❌ 禁用

| 禁用词 | 为什么 | 正确写法 |
|---|---|---|
| **软件主体** | 与「宿主」同义，徒增混乱 | 主程序 |
| **宿主**（指本项目程序时） | 与浏览器「宿主页面」撞车 | 主程序 |
| **Native Host** / **native host** | Chrome 的技术术语，指 NM 宿主程序。本项目 NM 宿主是 `fs-host`（通道），不是主程序 | 主程序（若指 fs-gui）/ NM 桥（若指 fs-host / 通道本身） |
| **GUI 宿主** | 同上 | 主程序 |

### ⚠️ 「宿主」唯一允许的用法

浏览器/Shadow DOM 术语，指**被注入脚本的网页 DOM**，与本项目程序无关，**保持原样不动**：

- ✅ `避免污染宿主页面`（指网页）
- ✅ `宿主页内浮层`（指网页）
- ✅ `宿主元素的 light DOM 子节点不会被渲染`（Shadow DOM 术语）

判据：句子主语是**网页/页面/DOM/元素** → 保留「宿主」；指**咱们的 exe** → 改「主程序」。

## 三、代码标识符一律不改（2026-10-04 决策）

用户已明确：**只统一文案，代码标识符保持不动**。理由：零风险，无需重跑 NM 注册与真机复验。

以下**禁止重命名**：

- 目录 `crates/host`、包 `fs-host`、可执行文件 `fs-host.exe`
- NM 宿主名 `com.fullscene.ocr_translator`（**注册表已写入**，改了扩展连不上）
- `scripts/register_nm_host.mjs` / `.cmd` / `unregister_nm_host.*`（脚本名与文档、菜单多处交叉引用）
- 注册表项 `Software\Google\Chrome\NativeMessagingHosts\com.fullscene.ocr_translator` 等三项
- 扩展侧 `extension/src/nm/` 下的 `NM_HOST` 常量、`connectNative` 调用

需要指代这些标识符时，写成：**「主程序」（`fs-gui`）**、**「NM 桥」（`fs-host`）**。

## 四、扩展侧的对照说法

扩展向主程序发请求时，统一表述为：

- ✅ `向主程序发请求` / `主程序未运行` / `主程序未连接`
- ❌ `宿主未运行` / `调用宿主` / `Native Messaging 宿主`
